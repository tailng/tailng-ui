Graph inputs

The required model inputs are definition and snapshot. The graph is otherwise controlled through the same state channels as the editor surface.

  • definition: workflow graph definition.
  • snapshot: run, node, and connection execution state.
  • selection, inspectedNodeId, and selectedExecutionId: controlled interaction state.
  • viewport: controlled pan and zoom state.
  • mode: edit, inspect, or readonly. This is the only graph interaction-mode input.
  • attachmentLayout="custom-points": displays three connection positions on each node border for free-form authoring. The default static-ports layout renders only ports declared by the workflow definition.
  • showControls, showBackground, showMinimap, showSelectionArea, and fitOnInit: surface feature toggles.

Graph outputs

Listen for selectionChange, inspectedNodeIdChange, selectedExecutionIdChange, viewportChange, and executionActivated to keep inspection state synchronized. In edit mode, apply nodesMoved, nodeCreateRequested, connection create/reconnect/waypoint requests, and node/connection delete requests to a new controlled definition snapshot. These outputs are proposals: the graph never mutates definition internally.

Controlled connection authoring

When accepting connectionCreateRequested, assign an application-owned ID, append the new connection, and persist custom-point endpoint ports with ensureTngFlowCustomPointPorts(). Apply connectionsDeleteRequested by filtering those IDs from the definition, clearing stale selection, and calling pruneUnusedTngFlowCustomPointPorts().

Imperative helpers

The graph forwards layout and viewport helpers such as refreshLayout(), fitToScreen(), resetViewport(), and centerNode().
